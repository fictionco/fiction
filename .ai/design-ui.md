# Design & UI Rules

## Core Design Philosophy

- Design is for **clarity and conversion**, not decoration or entertainment.
- Every screen should have **one main thing** it wants the user to understand or do.
- Follow **first principles**: eye-tracking patterns, reading flow, visual hierarchy, minimal cognitive load.
- The interface **is the brand** — it should communicate restraint, competence, and precision.

## Format-Specific Layout Rules

### Landing Pages
- Single-column layout by default.
- Hero sections may be centered (max 3 lines of text).
- Tours, walkthroughs, or multi-step content: all text on the same side (left or right). Never alternate sides.
- Never use feature grids, product benefit tables, or pricing blocks that feel overwhelming.
- Visual simplicity = perceived simplicity of product.

### Dashboards
- Single-column, feed-oriented layout.
- Show user momentum or clear next steps.
- No complex data density unless expert users require it — hide advanced elements by default.

### Emails
- Think of emails as mini landing pages.
- Single action. Single column. No fluff.
- Avoid generic headers like "We're excited to announce…"

### Indexes (e.g. posts, plugins, releases)
- Grid allowed here. Prioritize scanability.
- Avoid busy cards. Focus on clear titles, dates, and value per row.

### Long-form Content
- Moderate line length (60–75 characters).
- Avoid over-formatting: no sidebars, no inline ads, no footers that compete with the narrative.
- Keep typography invisible. The content should be the focus.

## Layout Heuristics

- Max line length: **60–75 characters**
- Max words per screen: **~200**
- Only center-align if: max 3 lines, hero section, or short headlines
- One primary action per view — others must be clearly secondary
- Use whitespace before borders to define visual separation
- Use grid systems only to support scanning, never to present complexity

### DON'T:
- Alternate image/text left-right (visual zig-zag)
- Stack multiple equal-weight CTAs
- Use carousels, tabs, or hidden content for anything critical
- Add animations that don't support clarity

### DO:
- Show one benefit or idea at a time
- Keep all messaging aligned for rhythm and flow
- Use visual rhythm (spacing, typography) to guide user attention
- Use contrast and spacing to establish hierarchy, not decoration

## Editorial Minimalism

- Remove every element that doesn't clarify, sell, or guide.
- If a block of text or UI doesn't help the user take action or understand value, delete it.
- Each screen = one message. Each message = one supporting visual.

### DON'T:
- Add icons unless they directly clarify
- Use subheads that restate headlines
- Include visual "noise" like random illustrations or mood images

### DO:
- Use SVG mockups or simplified screenshots — no busy UIs
- Let content speak through structure and rhythm
- Make the outcome feel obvious without over-explaining

## Conversion & Sales Psychology Principles

- Clarity converts. Don't write to impress — write to remove hesitation.
- Use visual framing to build **momentum** — each section should build toward action.
- Loss aversion > gain seeking: highlight what users *miss* by doing nothing.
- Present tense > future promise: show the benefit as immediate.
- Use social proof only when **concrete** and **specific** (e.g. "Used by 3,000 operators with no team" > "Trusted by professionals").

## Visual Behavior Rules

- Animations only allowed when:
  - Emphasizing a key point
  - Clarifying hierarchy or direction
  - Improving flow between steps
- Never animate just to "delight" — delight is achieved through clarity, not gimmicks.

## Allowed Visual Elements

### ✅ ALLOWED:
- SVG mockups (clean, simplified, avoids distracting UI)
- Inline screenshots (blurred background detail if complex)
- Subtle animation (contextual, informative only)
- Sparse iconography (meaningful only)

### ❌ FORBIDDEN:
- Hero images with random floating objects
- Decorative gradients or noisy backgrounds
- Feature tables or multi-option pricing with dense copy
- Flipping image-text layouts or zig-zag walkthroughs

## Universal Design Checklist

- [ ] Is there one clear thing to understand or do?
- [ ] Is the text readable at a glance?
- [ ] Is the layout helping, not distracting?
- [ ] Does each element earn its place?
- [ ] Is there momentum toward action?
- [ ] Would a smart non-designer immediately know what this is and why it matters?
